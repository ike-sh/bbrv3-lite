## 1. 根因、调用链与审计范围

正式基线 `4b9bb71d5b797dcf115863fbcb27b7fd4350f17e` 的 `src/kernel.sh:102` 在安装 gnupg/curl 前执行 `require_commands apt-get apt-cache curl gpg`，故精简系统缺少 gpg/curl 时，依赖安装不可达。已使用 `git show` 独立读取原代码，原文见 baseline-kernel-v808.txt（仓库外证据：`baseline-kernel-v808.txt`）。新 fixture 的 legacy case 继续重现该顺序缺陷。

实际修复调用链：

```text
cli.sh:1124 kernel_menu / cli.sh:381 cmd_kernel
  → kernel_install (kernel.sh:221)
  → root / lock / track / OS / amd64 / container / existing Secure Boot guard
  → require apt-get apt-cache dpkg-query; validate codename
  → kernel_bootstrap_dependencies (:89)
      strict APT update → identify missing ca-certificates/curl/gnupg
      → apt_network_guard (:75) → install --no-remove → verify curl/gpg
  → kernel_install_repository (:159; scoped subshell)
      official HTTPS key → parse → dearmor → parse converted key
      → compare existing paths → atomic no-overwrite publication
      → signed-by APT update → unchanged CPU/track candidate selection
      → apt_network_guard → install --no-remove
      → check update-grub when available → package-installed message
  → scoped cleanup; caller EXIT/lock semantics preserved
```

入口、预检及安装后验证见 [src/kernel.sh:221](../src/kernel.sh#L221)、[bootstrap:89](../src/kernel.sh#L89)、[repository:159](../src/kernel.sh#L159)。`die` 返回失败而不退出整个 shell，因此本次新增的显式 `|| return` 也在菜单条件调用中防止越过错误；44 场景确实在条件调用下测试。

本轮没有修改运行时源码或测试。仅补齐 [Release Notes](release-notes-v8.0.9.md)，同步 README/CHANGELOG 的候选链接与验证边界，并生成本报告。工作区中既有 hotfix 实现仍保持未提交状态；下面的 diff 身份覆盖完整候选相对 v8.0.8 的变更。
