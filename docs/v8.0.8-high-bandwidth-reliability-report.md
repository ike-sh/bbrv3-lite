# bbrv3-lite v8.0.8 High-Bandwidth Reliability Report

日期：2026-11-13（Asia/Shanghai）。开发基线：正式 v8.0.7，`0f6f686598f1a31df1f78bebb9942a6171113f6c`。v8.0.8 仍为未提交、未发布的本地开发版本。

本轮实现预算可完成性评估、参考样本资格、决策置信度、未完成 knee 的历史语义、Peer Health 计数分离和 TSV 写入完整性保护。默认 hard TX budget 仍为 6 GiB。现场中断的正确新结论是：sample confidence 可以 high，decision confidence 为 low/inconclusive；`LAST_CLEAN=1160`、`SUSPECTED_BREAK=1222`，无 confirmed break/knee、无 recommendation。

## Root Causes

### 1. RATE-1036 的参考样本资格检查顺序错误

v8.0.7 调用链：`measure_sweep → measure_level_with_confirmation → sample_repeated(count=1,max=1) → loss_spike`。首个样本只要没有 loss spike，就直接被返回；随后 `measure_sweep` 才执行 `minimum_efficiency_ratio(base_gp,low)`，并无条件设置 `CLEAN_REFERENCE_*`、`LAST_OK`。证据：正式提交 `src/measure.sh:1415` 的 level 检查，以及 `src/measure.sh:1908` 的参考赋值顺序。

`631.58 / 1036 = 60.96%`。旧函数先算 `0.6096 × 0.98`，再把结果钳到原有下限 `0.75`；这个下限只约束后续扫描/确认，没有回头检验首个样本。因此 `MIN_EFFICIENCY_RATIO=0.75` 与接受 61% 的首个样本并不矛盾，真正的问题是漏检自身。

新链路：[level 资格检查](../src/measure.sh)中的 `measurement_throughput_representative → measurement_level_sample_audit → 有界同档复验`，在参考赋值前完成资格检查。初始参考使用原有 0.75 下限，后续使用参考推导的既有动态门槛。

### 2. budget-exceeded 绕过 decision confidence 降级

v8.0.7 在 `src/measure.sh:1985` 设置 `SCAN_DECISION=budget-exceeded`，随后 `src/measure.sh:2009` 只检查 `inconclusive-*` 或非 clean PATH_CONTROL。预算中断不匹配这个前缀，PATH_CONTROL 又确实 clean，所以进入复制 sample confidence 的分支，生成 `100/high/clean`。

新链路：`measure_sweep → measurement_decision_confidence`，只有完成的 `recommend + confirmed + break` 或 `no-knee-clean + NO_KNEE` 可以继承遥测置信度；其余返回 0/low。[失败历史定稿](../src/diagnostics.sh)还在任何非零 RC、外层 rollback、final verify 失败时执行 `measurement_history_invalidate_decision`，覆盖 legacy `CONFIDENCE_*` 并清空 recommendation。

### 3. KNEE_MBIT 原来是无条件 LAST_OK 别名

正式 v8.0.7 的 `src/measure.sh:1998` 将 `${last_ok}` 无条件写入 `KNEE_MBIT`。它在现场表示“最后一个干净扫描档位”，并非已确认 knee；旧 history UX 又直接显示该值。

现在 `LAST_CLEAN/LAST_OK` 保留最后干净档位；`SUSPECTED_BREAK` 保留已观察但未完成确认的跳变；`CONFIRMED_BREAK` 要求原有 break 证据；`CONFIRMED_KNEE/KNEE_MBIT` 只在候选确认完成、扫描成功时填写。失败定稿清空 recommendation 与 confirmed knee。旧 history 只读解析也检查确认链，旧版错误的 high confidence 会在显示时降为 low，不改写旧文件。

### 4. 预算提示晚于真实容量发现，且旧上界不等于完整成本上界

原先直到 SATURATION/PATH_CONTROL 之后才输出粗略 sample/traffic upper bound，没有基于剩余接口预算的可完成性门控。向导对已知带宽的显示还会把估算裁到 hard budget，容易将“执行上限”误读为“足以完成的消耗”；未知带宽则只有固定 3–8 分钟提示。

新链路：`measure_sweep → measurement_budget_feasibility_gate → measurement_usage_update + measurement_remaining_plan`，位于第一次扫描与预扫描冷却前。模型使用实测 receiver/sender 与剩余阶段，显式区分 expected、完整分支 upper bound 和 hard limit。向导不再裁剪估算，也不再预先承诺固定耗时。原有 `measurement_budget_reserve_sample → measurement_budget_check → interface_counter` 的强制执行链未改动。

### 5. Peer Health 的分子和分母不是同一单位

原链路：`iperf_sample` 的 busy/reset/timeout 在每次尝试失败处调用 `peer_health_record(failure)`；成功原始样本没有对应成功事件。`measurement_peer_health_finalize` 只有完整 probe/sweep/verify 返回 RC0 才调用 `peer_health_record(success)`。`peers_show` 用 `SUCCESS_COUNT / (SUCCESS_COUNT + FAILURE_COUNT)` 显示 Success，混合了成功操作与失败尝试。因此 11 个成功 iperf 样本仍可显示 `Success 0/4`。

新链路：`iperf_sample → peer_health_record_sample_success` 独立增加有效会话数，操作结束再单独增加 completed-operation / completed-sweep 计数。评分采用独立样本尝试窗口，完整操作不会伪装成样本事件。原 `SUCCESS_COUNT/FAILURE_COUNT` 保留兼容，UX 不再显示混合单位的成功比例。

### 6. RTT nams 是字符串拼接问题

旧 `peers_show` 直接输出 `${PH_LAST_RTT_MS}ms`；缺失值 `na` 因而变成 `nams`。现在先验证 RTT：有数值才追加 `ms`，否则输出 `n/a`。失败尝试也不再用未知 RTT/吞吐覆盖已有有效遥测。

### 7. 现场 TSV 损坏尚不能确认

没有收到原始生产 `samples.tsv`，不能把终端复制异常当作结论，也不能声称已验证现场原始文件。正式代码的 header 和行格式均具有 20 个 Tab 分隔字段。当前实现保持该 schema，增加逐单元格 Tab/CR/LF 拒绝后整行追加，并用实际 writer、生产输入 fixture 和 legacy history 测试验证。

## Decision Confidence

| 状态 | Sample confidence | Decision confidence | recommendation / confirmed knee |
| --- | --- | --- | --- |
| budget exceeded / feasibility 不足 | 已采集的完整稳定样本可 high | 0 / low，inconclusive | 空 |
| peer unavailable / busy / reset / timeout | 取决于已有有效样本 | 0 / low | 空 |
| bad baseline / PATH_DIRTY | 保留遥测质量，不表示线路干净 | 0 / low | 空 |
| unstable / contaminated samples | 保留已有样本质量 | 0 / low | 空 |
| policer suspected，但无 confirmed knee | 可 high | 0 / low | 空 |
| candidate not confirmed | 可 high | 0 / low；返回 RC2 | 空 |
| clean no-policer，实验完成 | 按样本质量 | 可继承样本等级 | 无 HTB 推荐；仍遵守原 final verify 流程 |
| confirmed policer，候选确认完成 | 按样本质量 | 可继承样本等级 | 已确认值 |
| final verify failed / rollback failed | 有效样本可 high | 0 / low；同步降级 originating sweep | 清空 |

`SAMPLE_CONFIDENCE_*` 是遥测质量；其 `clean` reason 不代表重传为零。`DECISION_CONFIDENCE_*` 和 sweep/verify 的 legacy `CONFIDENCE_*` 反映证据链。自动调优成功后，操作级决策置信度不高于 sweep 样本与 final verify 二者较低值；现有 degraded FQ fallback 也不会得到 high。

## Reference Representativeness

RATE-1036 的 sender 635.66 和 receiver 631.58 都明显没有填满请求档位。两次 busy 发生在之前，而后续 1098/1160 的 receiver 分别达到 1036.75/1093.99，说明单个低速点不能作为稳定容量上限。现有材料无法确定它究竟由服务端竞争、TCP 恢复、短时本机调度还是其他因素造成；busy 是线索，不能据此认定因果。`CONTAMINATED=0` 只说明未命中现有本地污染阈值。

新行为：

1. 分开记录 `LOSS_CLEAN`、`THROUGHPUT_REPRESENTATIVE`、`PEER_LIMITED`、`PATH_DIRTY`、`CONTAMINATED`。
2. 首次低效 clean-loss 点不成为参考；冷却后在相同 shaping 档位复验，所有尝试继续走相同 hard-budget 预留与接口账本。
3. 最多三个实验；出现低效样本后，两个有效干净样本且二者满足原有 6% 稳定度门槛，才能恢复参考资格。两个低效点已使 quorum 不可能时，停止无意义的第三次，返回 slow/peer-limited/inconclusive，可按既有策略 failover。
4. 重传尖峰仍严格使用原来的三次实验、至少两次命中。低效但无 spike 的点不能替代 clean throughput reference；未完成第三次时不宣布 break。
5. 已有合格参考和 saturation 丢包证据后，后续同档重复确认的稳定平台可以参与原有两个档位 stall 算法，但不更新 LAST_CLEAN，也不成为 clean reference；仍要候选确认与 final verify。这保留了历史 `306 clean / 308 plateau break / 296 recommendation` 回归，避免把参考样本资格改动变成 knee 算法删除。

SATURATION 的 receiver median/完整真实 tuple 选择未改动：`386.30, 1144.06, 1138.46 → 1138.46`。前两次 spread 99.03% 触发第三次；最终 robust spread 0.73%，稳定双样本群允许 sample confidence high。outlier、追加原因和最终稳定度写入 [sample-events.tsv](validation/v8.0.8/production-replay-events.tsv)。PATH_CONTROL 原有 70% 效率与 0.5% 重传检查保持不变，现场代表值仍为 485.33 Mbit/s / 0.04603%，quality clean。

## Budget Feasibility

模型在取得容量/路径遥测后、首个扫描点前运行。起始 unknown-link 首样本安全预留和 6 GiB 默认预算不变。

机器字段包括 `HARD_BUDGET_BYTES`、`USED_TX_BYTES`、`REMAINING_TX_BYTES`、`EXPECTED_REMAINING_TX`、`CONSERVATIVE_REMAINING_UPPER_BOUND`、`EXPECTED_REMAINING_SAMPLES`、`PLANNED_SAMPLE_UPPER_BOUND`、`EXPECTED_DURATION`、`RETRY_ALLOWANCE`、`SELECTED_PROFILE`，另有模型/不确定性/剩余时间与样本上界字段。

| 当前场景（剩余阶段） | Expected TX | Conservative TX upper bound | Expected samples（含 allowance） | 剩余 sample upper bound | Expected remaining duration |
| --- | ---: | ---: | ---: | ---: | ---: |
| 200M standard；容量 191.38，183–220，step 6 | 3.17 GiB | 109.55 GiB | 21 | 360 | 181s |
| 1.14G standard；容量 1138.46，1036–1470，step 62 | 17.82 GiB | 766.48 GiB | 21 | 378 | 181s |
| 同一 1.14G 场景 quick | 12.99 GiB | 572.54 GiB | 21 | 360 | 147s |

以上都是当前 peer/path 剩余 sweep + final verify 的工作量估计，不是已经使用的 TX，也不是全局所有未来 peer 的保证总额。公共 sweep peer failover 后会重新发现容量并重新评估；切换 peer/port 的任何流量仍进入同一全局执行账本。

Expected 模型把实测容量约 108% 作为普通搜索中 break 位置的规划假设，计算粗扫、部分精扫、原有两组 spike recheck、候选确认、单双流 final verify，再加入两个完整样本的 retry allowance。108% 是参考约 1.14G 和 200M 现场轨迹的粗略规划位置，尤其 1222 只是 suspected spike；它不是新 knee 阈值。显示明确标注 uncertainty high，不把这组数字作为精确预测或完成承诺。

Conservative 模型枚举整个剩余扫描区间、最多三个下降控制点、最多七个精扫点、各档位最多三次实验、profile 的候选/verify 最大样本，再覆盖默认 3 次 transport attempt × 2 个 contamination 尝试的完整会话上界。它很宽松，也不按 hard budget/time budget 截短，不能宣传为必然消耗。Expected/upper 的差距正是潜在重试和未知 break 位置的不确定性。

可完成性风险仅在 expected 超过剩余 TX 或预计总耗时超过 hard duration 时触发；不会仅因 worst-case 上界超过 6 GiB 就拒绝正常 200M 测量。交互用户可明确选 quick、输入更高 GiB 或取消 rollback；quick 仍不足时继续提示，不能假装完成。非交互模式返回 RC70，提示 `--measurement-profile quick`、`--max-test-gib`、必要时 `--max-duration`。没有自动加预算、自动换 profile、重置账本、缩减必要证据或复用未验证候选。

[正常入口预算评估](validation/v8.0.8/early-budget-plan.tsv)展示在扫描前安全拒绝；[对应 summary](validation/v8.0.8/early-budget-summary.tsv)显示 low/inconclusive。重放原晚期中断时保留精确 snapshot：

```text
hard budget       6442450944 bytes
actual TX         5739233591 bytes
remaining          703217353 bytes = 670.64 MiB
next reservation  1200981349 bytes ≈ 1.12 GiB
```

下一次真实 `iperf_sample` 在 reservation 失败后没有进入 `timeout iperf3`。另有原始 iperf busy→success 测试证明 busy 2048 bytes 与成功 retry 1100000 bytes 均计入同一账本，初始化次数仍为 1。历史 v8.0.6 测试继续验证 peer failover、final verify 和 retry 不重置 ledger。

## Peer Health

| 新显示项 | 单位 | 兼容性 |
| --- | --- | --- |
| Sample success | `iperf_sample` 正式会话完成且解析有效的次数，含未完成 sweep 中的样本；不包含低流量预检 | 新计数，不从旧操作数推算 |
| Completed sweeps | RC0 的完整 sweep 次数 | 新计数 |
| Completed ops | RC0 的 probe/sweep/verify 操作次数 | 保留旧 SUCCESS_COUNT |
| Busy / Reset / Timeout attempts | 对应失败的正式 iperf 尝试次数 | 保留旧原因计数 |

schema 1 严格只读兼容，新事件到来时原子写为 schema 2，保存新计数起算时间；schema 更新于当前版本的文件（包括未知新字段）拒绝覆盖。评分的近期 12 次 iperf 尝试窗口不混入 completed operation；旧窗口仅作为 legacy prior。原到期 penalty、一天减权/一周归中性、同 host/address/family/port 独立及 live precheck authoritative 的行为仍保留。

晚期重放显示 Sample success 13 / Completed sweeps 0 / Completed ops 0 / Busy 4 / Reset 0 / Timeout 0。13 = 11 条现场成功输入 + 两条为新资格恢复构造的同档有效样本；不是声称现场原来有 13 条。[Peer Health 输出](validation/v8.0.8/production-replay-peers.txt)明确标注单位。缺失 RTT 测试输出 `n/a`；slow/inconclusive 不增加 PATH_DIRTY_COUNT。

## Evidence and Remaining Acceptance

容器内仅使用 fixture、loopback 与 disposable 网络命名空间。当前 Windows/WSL 环境通过现有 Docker Desktop 与临时 CLI 路径适配运行矩阵，没有修改项目 Docker 验证脚本；最终矩阵按项目 CI 的方式使用 `BBRV3_DOCKER_IMAGES` 分别并行验证四个镜像。没有在用户生产 VPS 上运行高流量测试。
