**资格结论：`P3_QUALIFIED`。** 本结论针对本轮约定的差异审计及轻量资格复验：独立确认预算强制执行、测量算法、事务及 rollback 未改变，继承旧 P3 对这些未变路径的真实证据；RC1 新构建在同一真实 VPS 完成原始证据只读解释、隔离三类预算失败重放、CLI/history/TSV 一致性和生产完整性核验。P3-A-01 的“仍有余额却声称已耗尽”问题在该范围内已关闭，未发现未解决的 correctness 问题。

原始 root cause 是 `failure_reason_explanation(budget-exceeded)` 只凭 umbrella reason 输出“硬预算已耗尽”。真实执行是在 `measurement_budget_feasibility_gate` 发现 expected remaining 超过正余额后正确 RC70；原 writer 和 CLI 共用的说明却把预判不足写成实际耗尽。现有修复调用链是：

```text
measurement_budget_check / measurement_budget_feasibility_gate
  -> failure_set(..., optional rejection snapshot)
  -> failure_pending_write / failure_pending_load
  -> measurement_finalize_run
  -> summary.tsv + failure.tsv
  -> shared explanation + CLI + history readers
```

RC70、`FAILURE_REASON=budget-exceeded`、`SCAN_DECISION=budget-exceeded` 和 `MEASUREMENT_STATE=MEASUREMENT_BUDGET_EXCEEDED` 是保留的兼容接口。实际新增 subtype 名为 `BUDGET_FAILURE_SUBTYPE=exhausted|insufficient-reservation|feasibility-rejected|unknown`；任务中的 actual-exhausted / reservation-insufficient 是语义描述，没有据此重命名冻结 enum。A 是实际 TX/时间达到上限；B 是正余额不足下一阶段 reservation；C 是容量发现后的原 feasibility gate 拒绝当前剩余计划。只有 A 使用“已耗尽”。
